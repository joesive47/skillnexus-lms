AI SKILLS · INTERACTIVE SCORM 1.2

AI Coding Assistance:
เปลี่ยนแนวคิดเป็นนวัตกรรมด้วย AI

เปลี่ยนโจทย์ธุรกิจให้เป็นต้นแบบดิจิทัลที่ทดสอบได้ ด้วยวิธีคิด Prompt–Plan–Verify ที่ทำงานร่วมกับ AI Coding Assistant อย่างรับผิดชอบ

วางโจทย์ให้ชัดเขียน Prompt ที่นำไปทำงานได้ตรวจงานและทดสอบอย่างมืออาชีพปกป้องข้อมูลสำคัญ
ช่วงที่ 1 จาก 520%

1. เริ่มจากปัญหา ไม่ใช่จากโค้ด

AI Coding Assistant ทำงานได้ดีที่สุดเมื่อเราเริ่มจาก “ผลลัพธ์ที่คนใช้ต้องการ” แล้วค่อยแปลงเป็นงานย่อยที่ตรวจสอบได้

1
Who

ใครคือผู้ใช้ และกำลังเสียเวลา/เจอปัญหาอะไร

2
Outcome

เมื่อสำเร็จ ผู้ใช้ทำอะไรได้ดีขึ้นอย่างวัดผลได้

3
Scope

ต้นแบบรอบแรกต้องทำอะไร และยังไม่ทำอะไร

4
Evidence

เกณฑ์รับงานและตัวอย่างผลลัพธ์ที่ถือว่าใช้ได้

คิดเหมือน Product Owner: เขียน 1 ประโยคให้จบว่า “ช่วยให้ [ผู้ใช้] ทำ [งาน] ได้เร็วขึ้น/แม่นขึ้น โดย [วิธีวัดผล]”

2. Prompt ที่พาไอเดียไปถึงงานจริง

อย่าขอแค่ “สร้างเว็บให้หน่อย” ให้กำหนดบริบท เป้าหมาย ข้อจำกัด และรูปแบบผลลัพธ์ก่อนเสมอ

บทบาท: คุณคือ Senior Frontend Engineer และ UX reviewer บริบท: ทีม HR ต้องการฟอร์มขอลางานภายในองค์กร เป้าหมาย: สร้าง responsive prototype ที่บันทึกข้อมูลจำลองได้ ข้อจำกัด: ใช้ Next.js + TypeScript, ไม่ใช้ข้อมูลจริงหรือ API key เกณฑ์รับงาน: มี validation, empty/error state และ test case 3 กรณี รูปแบบผลลัพธ์: เริ่มจากแผนไฟล์และ acceptance criteria ก่อนเขียนโค้ด
ถามให้ AI คิดก่อน

ขอแผน สถาปัตยกรรม และความเสี่ยงก่อนสร้างไฟล์

สั่งงานทีละส่วน

แยก UI, validation, persistence และ tests ออกจากกัน

3. จาก Prompt สู่แผนสร้างต้นแบบ

ต้นแบบที่ดีไม่จำเป็นต้องใหญ่ แต่ต้องพิสูจน์ได้ว่าแนวคิดนั้นมีคุณค่าต่อผู้ใช้จริง

A
Define

ระบุ user flow ตั้งแต่เริ่มจนเห็นผลลัพธ์

B
Design

ขอ wireframe และสถานะ empty/loading/error

C
Build

สร้างส่วนเล็กสุดที่ใช้งานได้ แล้วรันเอง

D
Verify

ทดสอบตาม acceptance criteria และดู diff ทุกครั้ง

AI สร้างโค้ดได้เร็ว แต่ความรับผิดชอบต่อคุณภาพ ความปลอดภัย และประสบการณ์ผู้ใช้ยังเป็นของทีมเรา

4. ตรวจงาน AI ให้เหมือนมืออาชีพ

ใช้ checklist นี้ก่อนนำโค้ด AI ไปใช้จริง โดยเฉพาะเมื่อกระทบข้อมูลลูกค้า หรือระบบสำคัญ

Function

ทดสอบ happy path, input ผิดรูปแบบ และกรณีข้อมูลว่าง

Security

ไม่มี API key, password, token หรือข้อมูลส่วนบุคคลอยู่ใน prompt/code

Maintainability

ตั้งชื่อชัดเจน แยกความรับผิดชอบ และอ่าน diff ก่อน merge

Evidence

มี test หรือวิธีพิสูจน์ว่าเกณฑ์รับงานผ่านจริง

กติกาทอง: Never copy–paste blindly. อ่าน, รัน, ทดสอบ, แล้วจึงนำไปใช้
